Overview · 2 min

The system is a verification engine: it picks up a CRM event, fetches the agent's public profile, drives the right state's licensing site, and writes a verdict to a ledger. That sounds simple, but it has four sharp constraints:

  • 50 state sites, every one different
  • Some sites have anti-bot defenses, some don't
  • Site UIs change without notice
  • Cost has to stay flat as we scale — can't be linear in operator-hours

Those constraints shape the stack: durable orchestration (so transient failures don't lose work), tiered browser runners (cheap by default, escalate when the site fights back), AI as a fallback (so the bill doesn't explode), and config-as-data (so a new state isn't a new deploy).

YAML — config vs code · 2 min

The most common question we get: "if state flows are YAML, where does the logic live?" Short answer: YAML is declarative data; Python is the logic that reads it. The YAML is a recipe; Python is the chef.

What's in a YAML adapter

Selectors. URLs. A flow flag. The browser tier. No logic.

# verifier/adapters/wa.yaml — declarative only
state_code: WA
anti_bot_tier: T2
dre:
  search_url: https://professions.dol.wa.gov/s/license-lookup
  flow: multi_page_detail
  disambiguation_required: true
  selectors:
    license_input:
      - "input#License_Number"
      - "lightning-input[data-label*='License'] input"
    detail_expiration:
      - "text=/Expiration Date:?\s*([A-Za-z]+ \d{1,2},? \d{4})/i"

Where logic lives

Logic concernLives inWhy not YAML?
Reading the YAML and dispatching verifier/adapter_loader.py (Python) YAML can't loop, branch, or call functions
Driving the browser with fallback selectors verifier/playwright_runner.py (Python) Needs try/except, retries, screenshot timing
Disambiguating multi-row results verifier/disambiguator.py (Python) Token math, scoring, thresholds, decisions
Tier promotion / demotion verifier/anti_bot_router.py (Python) Stateful — tracks recent outcomes per state
Comparing CRM ↔ DRE expiration verifier/activities.py + Claude Haiku Date formats vary; LLM classifies robustly
The split is the point. Adapter authors edit YAML — selectors, URLs, expected types. Engineers edit Python — retry policies, disambiguation rules, router state. A bad selector change can be reverted with a YAML revert. A bad algorithm change goes through code review.

Browser automation · 2 min

Playwright T1 — default

Cross-browser automation library from Microsoft. Drives real Chromium, Firefox, or WebKit via a stable async protocol. We use the synchronous Python API for our workers. 

# Real example from the runner
with sync_playwright() as pw:
    browser = pw.chromium.launch(headless=True)
    page = browser.new_context().new_page()
    page.goto(url, wait_until="domcontentloaded")
    page.fill(selector, license_no)
    page.click("button[type='submit']")
AlternativeVerdictWhy not
SeleniumRejectedOlder, less reliable async model, weaker stealth, more flaky in CI
PuppeteerConsideredChrome-only; Node-only — we're a Python shop
CypressRejectedFor end-to-end testing of your own app, not third-party sites; sandbox limitations
Used by: Microsoft, Disney+, VS Code, BBC, Hulu, OpenAI (internal automation), TestGrid, Bright Data.

Camoufox T2 — stealth

A fork of Firefox with C++-level patches that defeat browser fingerprinting (canvas, WebGL, audio, timezone, fonts). Open-source. Same Playwright API as plain Firefox.

AlternativeVerdictWhy not
playwright-stealth pluginConsideredJS-level patches only — modern detection scripts beat it
undetected-chromedriverRejectedSelenium-based; same patching problem
PatchrightConsideredPatched Playwright fork; smaller community than Camoufox
Used by: Scraping firms, Bright Data customers, indie OSINT tooling. Smaller community than Playwright, but the only credible OSS option for serious anti-bot bypass.

Browserbase T3 — managed

Hosted browser service. You hit their API; they give you a remote Chromium with residential IP, CAPTCHA-solving plug-ins, and built-in observability. Costs ~$0.04/run.

AlternativeVerdictWhy not
Bright Data Browser APIConsideredComparable; Browserbase has nicer DX and recordings for free
Self-hosted Selenium Grid + proxiesRejectedMassive ops overhead; we'd need to maintain a fleet for <10% of traffic
ScrapingBee / ScraperAPIRejectedHTTP-only — can't run a multi-step browser session
Used by: Anthropic (Computer Use demos), Cognition / Devin, Vercel v0, Stagehand, Browser Use.

Workflow orchestration · 1 min

Temporal Production target

Durable workflow engine. You write workflows in normal Python; Temporal handles retries, replays, timeouts, and signals. A worker crash mid-run resumes on a new worker without losing progress. Our prototype uses an in-process generator-based saga that mirrors the same retry/replay semantics.

AlternativeVerdictWhy not
AWS Step FunctionsReal contenderJSON-defined workflows feel clunkier; great for AWS-natives though
AirflowRejectedBuilt for batch DAGs, not per-event durable workflows
CeleryRejectedTask queue, not a workflow engine; no replay or durable state
Hatchet, Inngest, Trigger.devConsideredYounger; Temporal has 7+ years of battle-testing at scale
Used by: Snap, Coinbase, Doordash, Stripe, Datadog, Yum! Brands, HashiCorp, Uber (original authors built Cadence which became Temporal).

LLM — Anthropic Claude · 1 min

Two roles: Haiku (fast, cheap) for the expiration-date classifier on every run; Opus (smart, expensive) for the HTML-extract fallback when CSS selectors miss (~5% of runs). Tomorrow: Opus vision for screenshot-based extraction.

AlternativeVerdictWhy not
OpenAI GPT-5ComparableQuality similar; Claude has stronger tool-use ergonomics and we already use Anthropic SDK
Google GeminiConsideredStrong vision, weaker general SDK; would re-evaluate for vision fallback
Open-weights (Llama, Mistral)RejectedSelf-hosting cost + ops overhead doesn't beat managed for our volume
Used by: Anthropic (obviously), Notion, Sourcegraph (Cody), Asana, Quora, Slack (AI features), Zoom, DuckDuckGo.

Data layer · 1 min

Postgres (RDS) Ledger

The verification ledger. Indexed on agent_id, run_id, state_code, verdict. Multi-AZ. PITR.

AlternativeVerdict
DynamoDBRejected — joins matter for Ops; SQL is the lingua franca of audit
MySQL / MariaDBFine — Postgres has stronger JSON + window function support
SQLite (prod)Rejected — local only; we use it for the prototype
Used by: basically everyone. Stripe, Apple, Instagram, Spotify, Reddit, GitHub.

S3 + Cross-Region Replication Artifacts

Screenshots, HTML snapshots, run traces. Cheap, durable, replicated to a second region for DR.

Used by: Netflix, Airbnb, Pinterest, every AWS-native company on earth.

Redis (ElastiCache) Selector cache

TTL'd cache of which selector worked for which state recently. Hot path skips the DOM scan and uses the cached one — falls through to the multi-selector list if it misses.

Used by: Twitter, GitHub, Pinterest, Stack Overflow, Snapchat.

Event bus — AWS EventBridge · 1 min

Schema-validated bus that delivers CRM events (agent.activated, license.updated) to the workflow trigger. Has a built-in archive + replay for back-fill scenarios.

AlternativeVerdictWhy not
SNS + SQSConsideredNo schema registry, no built-in replay window
Apache KafkaRejectedMassive ops overhead for one event topic at our volume
Confluent CloudRejectedCost-prohibitive for our throughput
Used by: Capital One, Liberty Mutual, EA, Salesforce (their own platform).

UI & observability · 1 min

Streamlit Demo + deck

Python-first web framework. We use it because the deck and the working build are the same app — live demo pages call the same workflow code that production would run.

Used by: Uber (internal dashboards), Tesla, Snowflake (data apps), Goldman Sachs, hundreds of ML teams for prototypes.

Mermaid Diagrams

Markdown-style diagram language that renders to SVG in the browser. We use it for flowcharts and the ER schema. Cheap to author, scales nicely, includes pan/zoom via svg-pan-zoom in our full-window popup.

Used by: GitHub (native rendering in READMEs), Notion (via plugin), GitLab, Bitbucket.

Slack webhook HITL

Incoming-webhook message with interactive action buttons. The button click resolves a durable workflow signal — the operator's decision moves the saga forward.

Datadog Telemetry

Spans per activity, golden-signal dashboards per state, error-budget burn-rate alerts. We don't manage observability infra ourselves.

AlternativeVerdict
Grafana + Tempo + LokiOSS but ops-heavy
New Relic / HoneycombComparable
CloudWatch onlyInsufficient — weak distributed-tracing story
Used by: Samsung, Comcast, 21st Century Fox, Coinbase, Peloton, Whole Foods.

Why this whole stack, in one paragraph · 2 min

Determinism cheap, AI on fallback. Selectors do 95% of the work; LLMs only fire when the DOM drifts. Stateless workers, durable workflow state. Pods can die and the workflow doesn't. Config-as-data, not config-as-code. Adapter changes are YAML diffs; engine changes are Python code review. Managed when reasonable. Pay for boring infra so engineer-hours go into the verifier itself, not the queue or the metrics pipeline. Optionality preserved. Every choice is swappable without rewriting the workflow — Temporal can become Step Functions, Camoufox can become Playwright with a stealth plugin, Claude can become a comparable LLM.

Three sentences worth memorizing

  1. It has to be cheap when nothing's wrong, and graceful when something is.
  2. Adapter-as-data, not adapter-as-code.
  3. AI is a fallback, not the headline.
